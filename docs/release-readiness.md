# Release readiness

Checkpoint: 2026-09-05. **Ready for internal demonstrations; a dependable paid launch is not established.** The application and standalone Windows package now have measured production, installation and replay evidence. Investigation reliability remains the main blocker.

The [latest frozen code-investigation cohort](../artifacts/live-model-qualification-production-launch-1788608737491/summary.json) qualifies **1 of 4 attempts**. All four signed Records independently replay. Qwen's clean case succeeds on its first probe; the other three attempts are INVALID. Three execution-feedback invocations produce no admitted repair. The run records 21 logical calls, six failures, 59 started provider rounds and eight distinct Docker executions. These two small fixtures do not estimate customer-workload reliability, and the successful first probe does not demonstrate repair or a causal improvement from the changed instructions.

The current [full workspace suite](../artifacts/provider-connections-source-validation.json) passes **1,319 tests with 14 skips and no failures**. All 950 [compiled files](../artifacts/provider-connections-installed-freeze.json) remained unchanged during package and daemon testing. Investigation, metabolism and original-source producer identities remain unchanged from the preceding installed method. Deterministic signed lifecycles establish [narrow original-source ACCEPT/REJECT/UNPROVEN](../artifacts/original-subject-installed-lifecycle-1788604306738/independent-verification.json) and [comparative repair with retained failed parents](../artifacts/comparative-repair-lifecycle-1788606210000/independent-verification.json). They do not establish model performance or qualify the new whole application build for customer workloads.

**Visual connection onboarding is now implemented.** The Chamber's Connections page discovers models from local services, selects compatible cloud APIs and origin-bound credential references, exports MCP client configuration and tests registered MCP servers. Profiles save for the next startup while active settings remain visible. The machine launcher honors saved choices; native Codex/Claude configuration remains separate. [Nine isolated browser checks](../artifacts/provider-connections-browser-source-v2/report.json), [four restart checks](../artifacts/provider-connections-source-fixture-v2/activation-proof.json), and [eight production browser checks](../artifacts/provider-connections-production-browser/report.json) pass. The live service listed 17 Ollama models. These are discovery and configuration checks: no cloud inference was run and the MCP handshake used an explicitly synthetic registered server. See [setup and boundaries](provider-connections.md).
