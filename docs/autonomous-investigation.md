# Autonomous investigation

Raw ModelAdapters have a Judge-owned inspection loop. One logical Mind invocation permits at most four provider rounds and four tool calls per round. Every repeated prompt and tool result is included in cumulative transmitted bytes and token accounting. Missing provider usage uses an observed-byte upper bound; inconsistent mixed usage fails closed. Available sealed source must actually be inspected before a final contribution is admitted. An early final receives a metered continuation request within the same four-round ceiling. The last round requires a final structured contribution, and there is no transport retry within this loop.

The tools read a provider-authorized catalog over the Case's sealed content-addressed snapshot, its initial text projection, and the current lane's visible public contributions. A small prompt sample no longer makes the rest of the captured repository inaccessible. The catalog addresses at most 4,096 files of at most 4 MiB each, with a 16 MiB scan ceiling per search, 80 lines per read, and a 32,000-byte encoded result ceiling. File listings paginate; search returns a file-and-line continuation cursor. Binary, empty, uninspected, oversized and policy-excluded material remains explicit. Every source read rechecks captured manifest and blob identities; empty or out-of-range reads never count as inspection.

Tools list files, read bounded line ranges, search literal text, query Tree-sitter symbols within the explicitly labeled initial projection, inspect public evidence, and list exact critical obligations and experiment templates. Files use opaque identities. Tools cannot read live host paths, execute commands, access a hidden lineage, or restore material withheld from a remote provider. `provider_scoped` and `local_only` withhold the source catalog from remote providers before resolving its material. Receipts bind argument, result, and source digests. Signed catalog descriptors and context observations do not become verdict evidence.

Task-specific inspection resolves explicit file references in the sealed impulse and constraints against the permitted catalog. Up to four small readable files require complete reads; listings, searches and partial reads do not satisfy those requirements. The common prompt supplies exact file identities and ranges without prescribing a transport. The raw HTTP loop can read four files in one declared JSON batch; a native agent uses its own registered tool channel and its stated bounds. Large, ambiguous, missing and excess references remain explicitly unresolved. This rule never follows instructions or new paths found inside a source file, model response or public contribution. Generated revision parents retain their separate inspection requirement.

Captured files also advertise their exact synthetic read-only OCI locations under `/subject/subject-####/`. The ordinal follows the original binding order, including declaration-only gaps; catalog limits cannot renumber it. A generated probe may import actual captured source at that location when its sealed command and image support the dependency. The location grants no host access. Explicit task output and exit requirements govern the probe; generic JSON/self-check defaults apply only when those requirements are absent.

Repository discovery now feeds an automatic diagnostic observer. Before sealing, a deterministic Tree-sitter planner discovers bounded dependency-free Node test suites and their static local dependency closure. Unsupported languages, package dependencies, loaders, scripts, dynamic imports and ambiguous configurations remain explicit refusals. With a startup-resolved, network-denied Docker Forge, the lifecycle can observe up to two supported original repositories before model investigation. A separate read-only package contains only the selected original closure, a fixed controller and its exact request. The complete original capture is not mounted, and the empty tooling workspace never enters the candidate population.

The observer retains its plan, original-file membership, package identity, fixed controller, request, raw Forge observation, raw controller output and resource receipt. Empty suites, skipped tests, incomplete streams and stdout impersonating test-runner output cannot be reported as complete successful diagnostics. Artifact bytes are deduplicated across the Case; wall time, CPU measurement availability and writable resources enter the original Forge budget before candidate experiments. Replay checks that prefix and refuses omitted output sidecars, substituted roots and understated readings. Model context receives bounded counts and diagnostic codes, with no hidden source disclosure.

These repository test reports have **no verdict authority**. A submitted JavaScript process can influence its runner's reporting channel; authentic Docker execution alone does not establish the truth of its assertions. The independent verifier separately reports source derivation, execution provenance and controller consistency while retaining `TRUSTED_EVALUATOR_BOUNDARY_MISSING`. An existing-suite failure guides investigation and reproduction. It cannot silently become a binding counterexample, and a passing report cannot satisfy a critical obligation without an applicable independent evaluator.

Failed model invocations retain a signed, digest-only diagnostic artifact: the failure boundary, started provider rounds, tool names and receipt hashes. Raw arguments, tool contents and provider text are excluded. The artifact is linked by an action event and cannot satisfy an obligation. This makes source-inspection failures distinguishable from malformed final contributions without disclosing a private prompt.

Construction returns finite candidate source for an already sealed experiment socket. Forge materializes and executes that candidate, and bounded feedback rounds can then inspect the actual failure and revise the committed parent. Each round admits at most one changed, parent-bound program. The kernel commits the feedback and appended population before running that new program against the original frontier. Two baseline feedback rounds share the existing Reflex call allowance; the final deterministic Reflex audit still runs. One union population reaches final assay selection, so failed originals remain visible and model feedback never gains verdict authority. Native AgentAdapters retain their own bounded transport and quarantine contracts.

Available parent source must be read through `list_revision_files` and `read_revision_lines` before raw models may submit a revision. Those tools use digest-bound generated files, and provider disclosure rules can withhold the files and captured output. Model prompts carry stable aliases for outcome context; the physical observation bindings remain in the committed feedback artifact. Replay reconstructs that feedback from preceding Forge observations, checks the original parent, loop bound, sealed frontier, population chain, resource prefix and complete final matrix. It refuses invented feedback even when replacement artifact and event hashes are internally valid.

The current feedback projector decodes authenticated exact output captures, up to 2,000 UTF-8 bytes per stream and 16 cells. It labels partial, missing and invalid captures explicitly, matches each repeated attempt by its physical observation digest, and withholds source/output before decoding when disclosure is denied. Only retained observed output is projected; it grants no oracle or verdict authority. The versioned baseline first considers unresolved critical failures, then actual comparative socket failures even when critical source truth already passes; its eligibility and parent choice independently replay. Historical revision policy retains its earlier critical-only behavior.

Revision instructions now schedule one complete executable repair of the exact generated parent as the default deliverable. Task-authorized application implementation and repair remain allowed in that generated candidate. Captured original bytes, supplied expected outputs and the sealed evaluator remain unchanged; when a task observes original-source behavior, a corrected source copy cannot replace it. If no admissible repair can be justified, one honest Reflex refusal remains allowed without fabricated source, certainty or success. The unchanged parser accepts either candidate or assessment, and all failures and resource/two-baseline-round limits remain. [Seven new prompt-contract groups plus 48 existing tests passed](../artifacts/revision-prompt-cohort-preparation-1788608532141/source-validation.json), including non-audit application repair and withheld-source refusal.

The baseline continues eligible observed failures only at or above the sealed heuristic value-per-cost threshold. Calibrated Inertia remains critical-failure-only and can lower that threshold for a separately bounded number of additional scents. A committed decision records actual observation digests, exact signed dose, original and lowered thresholds, and selected parents. Production and finite calibration share the revision request constructor and metered admission path; neither can create an evaluator or command after sealing. Each extra revision has its own share of the signed resource allowance.

Native function calling is the default raw HTTP model transport. Set `JEVYR_OLLAMA_INVESTIGATION_TRANSPORT`, `JEVYR_LMSTUDIO_INVESTIGATION_TRANSPORT`, or `JEVYR_OPENAI_COMPATIBLE_INVESTIGATION_TRANSPORT` to `structured` before startup for models that need constrained JSON requests. Native mode accepts authorized function calls or the declared `jevyr.context-tools/1` JSON request format; structured mode requests closed JSON responses and sends no native tools. A declared batch may contain up to four calls, including four exact required-file reads, while parallel native calls remain disabled. Both use the same tool whitelist, disclosure boundary, accounting and receipts. Unknown fields, conflicting native and structured requests, and excess calls are refused. The loop never extracts a presumed request from prose or Markdown fences. Source identities must resolve inside the authorized captured catalog (or the initial projection when no catalog exists); candidate commands remain constrained to sealed sockets.

Both HTTP transports share a strict final schema for each assigned stage. DIVERGE requires one finite candidate and constrains its command and executable entry file to the sealed experiment socket when one is available. INTERPRET permits only interpretation, claim, observation or test-plan kinds. Revision permits one candidate or Reflex assessment and constrains parent references to committed parents; other stages use the general contribution envelope with at most six entries. While mandatory inspection remains incomplete, the declared JSON response schema admits context requests. The final round requires a contribution and omits native tool definitions entirely. An early final still passes through the same stage schema, actual source-receipt requirement, strict parser and resource bounds. A model that cannot finish the required delivery still fails the contract; schema constraints do not turn a bad program into a successful result.

These HTTP response schemas are separate from the native AgentAdapter contracts. Codex app-server invokes registered dynamic tools, and Claude Agent SDK invokes registered Judge MCP tools. Their common prompt is neutral about tool encoding; neither harness decodes the HTTP JSON-batch format or receives its response-format schema. Their own receipt and final-envelope checks remain in force. No native provider's credentialed inference or qualification is established by HTTP transport tests.

Phenotype is a first-class digest-bound artifact. The sealed Case, Genome, and seed determine its roster order, experiment portfolio order, blind lineage count, and heuristic effort weights. Those parameters govern the actual nursery and assay scheduler. They do not sample verdict thresholds, change obligations, or grant capabilities. Identical inputs produce identical traits regardless of adapter discovery order. New Search Envelopes use `sha256-case-seed-frontier-v2`: run timestamps and signed grant receipt digests do not change investigation entropy or supplemental method identities. The legacy v1 rule remains supported for older sealed runs. Logical schedules are reproducible with held inputs and provider outcomes; this does not certify that a provider honors its supplied seed or emits identical content.

Under v2, the common provider prompt and parsed or Rule contribution identities use the semantic Case digest rather than the physical Run identifier. Host Seal, event, and receipt identities remain authentic and unique. Live witness observations and external adapters can still supply changing context. Controlled HTTP/CLI reruns authenticate the original signed Record and terminal closure, then compare the complete current admitted late-memory hint list against that Record before exposing any hint. A changed hint, ordering, weight, or missing admission invalidates the rerun. The kernel-linked comparison artifact includes the signed source envelope and Record digest. Retrieval and tribunal writes remain governed by the original policy; this guard cannot admit memory or silently turn recall off.

Checkpoint-bearing Juggler cases also support controlled execution reruns while retaining Juggler control. Same-seed execution requires the original semantic scheduler checkpoints. New-seed execution deliberately changes methods: each original kind and quantity is rebound, in order, to its first eligible checkpoint within the original source stage. This reproduces the addition pattern, not the original timing or trajectory. Every addition receives a fresh signature and must still be offered by the exact immutable allowance and current calibration. Missing source-stage eligibility invalidates the run. Additional outside doses are closed during reproduction. The source Record, its authenticated event prefix, checkpoint artifacts and original grant signatures are committed in a public replay-plan artifact and independently verified using trusted Record keys. Historical Juggler traces without these checkpoints are refused rather than assigned invented timings.

The evidence scheduler retains the exact admitted candidate by sealed assay population. It prioritizes unresolved critical obligations per declared cost, then incorporates actually observed decisive failures when choosing the next cell. It records each decision before execution. Replay verifies authorized cell identities, exact population closure, declared cost, and execution order. Its value scores are explicitly heuristic, not calibrated success probabilities or proof that a candidate is correct.

Critical challenge routing prefers distinct explicitly configured model families and providers and assigns every critical obligation to the selected challengers. `JEVYR_OLLAMA_MODEL_FAMILY`, `JEVYR_LMSTUDIO_MODEL_FAMILY`, and `JEVYR_OPENAI_COMPATIBLE_MODEL_FAMILY` supply configured family provenance; aliases are not parsed to guess it. The routing artifact records assignments and missing diversity. Assignment is not proof that a model completed a challenge, and two names or providers do not establish statistical independence. Only admitted executed or separately verified formal evidence can satisfy an obligation.

Startup seals `policy.investigationKernel`, including the actual loaded implementation bytes for these methods, the orchestrator, native agent harnesses and isolation helpers, and the growth nursery. Capability limits, including explicit model identity and loop limits, are also included in the policy. Source-condition and compiled runs have different exact implementation fingerprints. Older Records retain their original policy descriptors; method identity does not authorize newer code to issue old-policy verdicts.

New project defaults use `forge.missingDocker: "UNPROVEN"`. If the requested secure image is unavailable at startup, the runtime records the failed requested substrate and explicitly chooses an observe-only body before sealing. Readiness advertises no execution capability. An explicit `"INVALID"` retains the strict legacy failure behavior. No path falls back to host execution; loss of a sandbox that was resolved and admitted still makes the run INVALID.
