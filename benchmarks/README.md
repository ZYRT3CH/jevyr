# Measured release evidence

`node benchmarks/runner.mjs --validate-only` checks the strict 14-case corpus and mechanism intake records without claiming that any case ran. The corpus includes the repository itself as a directory subject, explicit historical and escaped incidents, and fixed seeds shared within wording pairs.

`node benchmarks/runner.mjs --url http://127.0.0.1:4317 --report artifacts/release-corpus.json` casts every case in Sovereign mode, authenticates the Seal, Record and terminal chain, and independently replays persisted evidence. Its report records case, run, policy, ledger and Record digests. A matching verdict without replay is a failed result. A corpus assertion may fail honestly: the impossible encoder requires actual disconfirming evidence, and a model asserting impossibility cannot pass that gate by declaration.

`node benchmarks/release-gates.mjs --run-tests --output artifacts/release-unit-evidence.json` executes fixed constitutional, memory, Genome and transport suites. It records command identity, wall timestamps, exit status, observed test count and exact output digests. Zero tests, unavailable tools and interrupted processes do not pass. This report distinguishes unit evidence from empirical release evidence, so hundreds of unit assertions cannot silently close an unrun model, browser, memory-first or voucher experiment.

The corpus report contains all 17 plan gates. It marks only direct observations as PASS and leaves unmeasured gates OPEN. Paired prompt verdict agreement alone does not establish wording invariance when evidence differs; signed public chain authentication alone does not establish an independently verified exported bundle. The public release remains blocked until all empirical experiments have measured evidence.

The separate finite ACCEPT/REJECT fixture runs exercise command-oracle adjudication using an exact sealed command and distinct exit-code observations. Those runs prove the execution and judgment plumbing; a successful fixture is not heterogeneous model evidence. Actual local-model runs must be reported separately, including their configured provider and execution substrate.

`node apps/cli/node_modules/tsx/dist/cli.mjs benchmarks/run-isolated-corpus.ts` runs the full corpus against a private Rule-only runtime using the compiled packages from the latest `pnpm build`. It freezes the repository's current ignored-aware source inventory before using it as the self subject, records each source-file digest, verifies the frozen source remains unchanged, and exports each terminal Case as a signed offline proof. Its output is baseline evidence, explicitly separate from model-produced runs.

`node apps/cli/node_modules/tsx/dist/cli.mjs benchmarks/collect-lifecycle.ts --report artifacts/lifecycle-EXAMPLE/report.json --output artifacts/lifecycle-evidence.json` imports saved lifecycle experiments. Repeat `--report` for more cases. It verifies all three DSSE signatures, exact signed identity bindings, terminal event closure, every artifact body against the signed index, and independently replays persisted assays. A report's declared `replay.valid` or `modelProduced` flag is never used as proof. `--trusted-key-id sha256:...` additionally anchors the signer to a key obtained outside the proof. Missing exports, tampered artifacts, or replay incompatibility fail intake and leave release gates open.

Formal certificates bind the actual checker module bytes. A compiled JavaScript runtime and a development TypeScript runtime therefore have distinct checker identities. Use the exact sealed build for replay. For development-created proofs, put `--conditions=development` after the tsx CLI in both the producer and verifier commands; use `--development` with `benchmarks/runner.mjs` when its target daemon uses that same source condition. A mismatch is reported as unsupported checker identity rather than silently substituting another implementation.

`node benchmarks/protocol-experiments.mjs --output artifacts/protocol-experiments.json` records each exact finite integration assertion instead of inferring gate success from a broad suite count. It covers the actual CLI, seven submission surfaces, one-way input rejection, all five voucher scheduler effects, privacy projection, source preservation, injected provider/Forge failures, durable corruption recovery, and memory ancestry. Pairwise policy experiments distinguish changed prose provenance from unchanged decision axes and reasons.

`benchmarks/aggregate-release.ts` combines these inputs with fresh verification. Supply repeated `--protocol-report` and `--lifecycle-report`, plus `--corpus-report`, `--memory-report`, and `--output`. It rechecks named runner outputs, every signed corpus proof against the unchanged canonical corpus expectations, the browser observation/source/runtime/artifact chain, and raw paired-model outputs. Every PASS carries its finite scope; the model experiment remains unsigned local evidence. See [buildout status](../docs/buildout-status.md) for measured files and remaining portability or remote CI checks.

CI runs frozen dependency installation, type checking, builds, and all tests on pushes and pull requests. Optional default-branch workflow dispatch can attest the exact tested compiled archive using Sigstore via `actions/attest`, and independently verify its source commit provenance. Attestation establishes build provenance; it does not change case verdict authority or assert that release gates passed.

## Live-model qualification

`node --import ./apps/cli/node_modules/tsx/dist/loader.mjs scripts/live-model-qualification.ts --config CONFIG --output artifacts/NEW_DIRECTORY --measure-recovery --execute` runs one predeclared cohort of local-provider investigations against the compiled runtime, one daemon per attempt, and exports every attempt as a signed offline proof. Without `--execute` it writes the manifest and a `PREPARED_NO_INFERENCE` report and makes no model call. A configuration without a `corpus` field runs the two fixed clamp fixtures, which remain the historical baseline and are never rescored. A configuration with `corpus: { kind: "generated", seed, taskPairs }` runs the generated family from `benchmarks/generated-source-fixtures.mjs`: seeded task pairs over five templates, each pair one clean and one planted-defect `source.mjs` with task-specific parameters that no memorized textbook version can supply, a truth oracle computed from the specification by the generator's own reference code, and six declared inputs. The manifest deep-equals a regenerated corpus and archives the generator bytes, so a changed generator cannot rescore an older cohort. Fresh-per-run tasks follow the LiveCodeBench, DyVal, GSM-Symbolic and Functional Benchmarks lineage; this is an application of that method, not a new one.

`node scripts/run-generated-cohort.mjs --config benchmarks/configs/generated-smoke.json --output artifacts/NEW_DIRECTORY` (or `generated-cohort.json` for the 160-attempt, 80-generation cohort) predeclares the denominators in `NEW_DIRECTORY-dispatch/dispatch.json`, runs the runner above, then `benchmarks/probe-recovery-measurement.mjs`, `benchmarks/verify-live-model-qualification.mjs`, `benchmarks/blind-source-arm.mjs`, `benchmarks/verify-blind-source-arm.mjs` and `scripts/summarize-live-model-qualification.mjs`, recording each step's exit code. The read-only steps run even when the runner fails; nothing is retried and no root is reused. The predeclared configurations pin the installed Ollama model digests, so a changed model refuses to run rather than silently changing the cohort.

`summary.json` now carries a diagnostic `priorOverride` block from `benchmarks/prior-override-measurement.mjs`. Every executed model probe on a defective fixture is classified as MATCHES_ACTUAL (the defective behavior was reported faithfully), MATCHES_INTENDED (the specified behavior was reported instead of the observed source), NEITHER or MALFORMED; the strict qualification comparison, the recovery declaration and every gate are unchanged. On the generated family the parameters cannot come from training memory, so MATCHES_INTENDED means the co-located specification overrode observation; on the clamp baseline specification recall and training recall are indistinguishable. This follows the context-versus-prior measurements of Longpre et al. 2021, Xie et al. 2023 and ClashEval 2024. Failure categories are reported per attempt in a fixed order, and unexecuted defective attempts stay in the attempt denominator.

`node benchmarks/blind-source-arm.mjs COHORT_DIRECTORY` asks each configured provider, once per seed and task pair, to implement the function from `qualification.json` alone, executes the answer in the hardened blind-memory container pattern against the declared inputs, and compares the blind vector with the intended vector, the defective source's actual vector and the with-source probe vectors decoded from the cohort's authenticated proofs. `node benchmarks/verify-blind-source-arm.mjs COHORT_DIRECTORY` recomputes every comparison from retained files without rerunning anything. Equality between a blind implementation and a with-source probe shows the probe reproduced the model's spec-derived belief; it does not measure model quality and holds no verdict authority. Generated cohorts measure a bounded fixture family, not customer workloads, and no result from them rescores the historical four-attempt cohorts.

The first smoke cohort, [artifacts/live-model-qualification-generated-smoke-1788654089769](../artifacts/live-model-qualification-generated-smoke-1788654089769/summary.json) (two generated pairs, one local Qwen provider, one seed), exercised every step: four attempts with authenticated replay, the recovery measurement, two blind generations executed and independently re-verified, and a summary with the prior-override block. Its 0/4 qualification, one MATCHES_INTENDED revision probe out of three executed defective probes, three crashed probes and three Reflex-stage provider failures are a pipeline check on a two-pair smoke configuration, not a measurement of anything. The 160-attempt cohort has not been run.
